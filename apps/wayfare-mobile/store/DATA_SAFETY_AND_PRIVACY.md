# Google Play Data safety & Apple App Privacy — Wayfare

Answers below match the shipped build (v1.3.0): no analytics, no ads, no crash-reporting SDK, no third-party identifiers.

## Google Play — Data safety form

**Data collected and processed on Supabase (our backend, acting as a service provider)** — only when the user creates an account; guests keep everything on-device.

| Category → type | Collected | Shared | Required / optional | Purpose |
| --- | --- | --- | --- | --- |
| Personal info → Email address | Yes | No | Required for an account | Account management |
| Personal info → Name (display name) | Yes | No | Required for an account | App functionality |
| Photos and videos → Photos | Yes | No | Optional | App functionality |
| Audio → Voice or sound recordings | Yes | No | Optional | App functionality |
| Location → Precise location | Yes | **Yes — see note** | Optional (route recording, weather) | App functionality |
| App info / other → User-generated content (journal text, budget notes, packing lists) | Yes | No | Required for the core feature | App functionality |

**Note on location sharing.** If the user switches on "Attach weather", their coordinates (rounded to ~100 m) are sent to Open-Meteo to fetch the weather. Declare Precise/Approximate location as **shared** for that purpose, optional, not for advertising.

**Security practices**
- Data is encrypted in transit (HTTPS/TLS): **Yes**
- Users can request data deletion: **Yes** — in-app (Profile → Delete account) and web: `https://prasadamal.github.io/ariyoo-clone/privacy/wayfare-delete-account.html`
- Independent security review: No

**Not collected:** financial/payment info, contacts, calendar, messages, web history, health, device or other IDs, diagnostics, advertising data.

## Android permission declarations (Play Console → App content)

| Permission | Why | Declaration |
| --- | --- | --- |
| `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION` | Record a route the user starts; optional weather lookup | Foreground (while-in-use) only |
| `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_LOCATION` | Keep recording with the screen off, with a visible notification | Foreground service type **location** — the user starts and stops it; core feature (route recording) |
| `RECORD_AUDIO` | Voice notes | Runtime prompt on first use |
| `USE_BIOMETRIC` | Optional app lock | — |

**Not requested:** `ACCESS_BACKGROUND_LOCATION`, camera, storage/media permissions (photos use the system photo picker). No "background location" declaration form is needed.

*Foreground-service demo video (Play requirement):* screen-record Route tab → Start recording → lock the phone → unlock and show the notification and the extended route → Stop.

## Apple — App Privacy ("nutrition label")

| Data type | Linked to user | Used for tracking | Purpose |
| --- | --- | --- | --- |

| User Content → Photos or Videos, Audio Data, Other User Content | Yes | No | App Functionality |
| Location → Precise Location | Yes | No | App Functionality |

**Tracking:** No. **Data used to track you:** none. Privacy manifest (`PrivacyInfo.xcprivacy`) is generated by the build.
