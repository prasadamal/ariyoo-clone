## Chat transition ownership

The reducer performs no networking, native calls or navigation. The screen owns effects and a synchronous in-flight operation lock; a keyed child owns the account/session lifetime. HTTP acknowledgement and socket echoes use server message IDs. A history failure preserves already displayed messages and offers retry. A failed send preserves the draft. Image-picker cancellation is a normal transition back to idle, not an error. No automatic send retry is added because the API lacks an idempotency contract.

The server, not the reducer, must authorize messages and room joins. This change preserves the existing HTTP endpoints and wire messages. It does not claim secure real-time membership, atomic question/session creation, server-side upload protection or production readiness.

## Deployment hardening (November 2026)

Socket handshakes now require the HTTP JWT and each join checks database session membership. Expired credentials disconnect. The mobile transport supplies its token. Uploads have a 5 MB memory cap, accept JPEG/PNG/WebP signatures only, authorize session membership before committing files, clean up failed database writes, and require membership for reads. Native image requests carry bearer authorization. Legacy Angular image rendering needs authenticated blob loading before web release. Question/session creation is transactional. Compiled server imports now resolve under Node ESM; production refuses weak secrets and unspecified CORS origins. Socket integration and device acceptance remain release gates.

November follow-up: API factory permits isolated HTTP/socket integration tests without starting a production listener. Anonymous sockets, outsider joins, invalid room IDs, anonymous image reads, spoofed image bytes and outsider uploads are regression checked. Database operations are stubbed in this suite; PostgreSQL persistence remains a separate gate. Login has a per-IP rate limit; production proxies must set TRUST_PROXY to the deployment's exact hop count. Registration/login validate inputs and normalize email. Demo seeding refuses production and requires DEMO_PASSWORD. Runtime Docker uses the generated Prisma client from the builder and runs as node. Angular chat downloads now use authenticated blobs, with cancellation and URL revocation. API credentials are restricted to the configured API origin by its interceptor.

## Small-launch update (17 November 2026)

These change rows above; the table keeps the earlier review for history.

- **A01 session hydration:** the cached user is validated on parse (a malformed cache signs out), then refreshed from `GET /api/user/me`. Any authenticated call answering 401 (deleted, suspended or expired) signs the app out through one handler. Profile answers are applied only while the same account is still signed in.
- **A02 register:** editing → validated locally (email, 12–72 byte password, terms accepted) → submitting → signed in. The API refuses registration without `acceptedTerms: true` and stores `termsAcceptedAt`. Login refuses suspended accounts.
- **A05 matching:** a question is assigned only to another, unblocked expert who shares a topic (least busy first); otherwise the session is created with no solver and waits in the **open queue**. `open → claimed` is one conditional update, so two experts cannot both take a question. The asker is never their own solver.
- **A06 session list:** one request generation per load; lists carry role, peer name and waiting state; conversations with a blocked person are hidden for both sides. Experts also see the open queue (idle → claiming → opened / already-claimed).
- **A07 active flag / closure:** a conversation is closed for writing when it is inactive **or** either participant has blocked the other; the server answers `CHAT_CLOSED` and the screen hides the composer.
- **A10 image attachment:** no permission step; the system photo picker returns only the chosen photo. picking → cancel / uploading → acknowledged / error.
- **A13 profile / topics:** actor identity always comes from the token (body `userId` is ignored); profile and password changes are validated; experts add and remove their own topics.
- **New A18 safety:** conversation open → report (reason, optional details) or block → blocked → conversation leaves both lists. Unblock from Profile. Members can only report or block someone they share a conversation with.
- **New A19 moderation:** report open → resolved / dismissed; account active ↔ suspended (suspension ends HTTP and socket access at the next request). Key-protected `/admin` routes; see `services/api/MODERATION.md`.
- **New A20 account deletion:** confirm with password → server deletes the account, every conversation it took part in and their photos → local session cleared without further server calls.
- **New A21 push:** permission undetermined → asked once (first question, or when turning on expert mode) → token registered to the signed-in account → removed on sign-out. Payloads carry a session id, never message text. Tapping one opens that conversation.
- **A17 release:** Expo SDK 57. There is no built-in server address; `npm run preflight` blocks a store build that lacks `EXPO_PUBLIC_API_URL` or the EAS project id.

Verification: `apps/mobile` → `npm run verify`; `services/api` → `npm test`, then `scripts/smoke-flow.mjs` against a migrated PostgreSQL database (CI runs it), which covers matching, the claim race, chat boundaries, photos, blocking, reporting, moderation and deletion end to end. Device acceptance remains a release gate: `apps/mobile/store/SUBMISSION_CHECKLIST.md` §5.

Still open: self-service password reset (needs an email provider), idempotent sends, closing a conversation by choice, ratings, and the Angular web app's parity with these safety features (it gained terms acceptance only).
