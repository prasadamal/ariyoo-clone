## Implemented transition contract

`syncState.ts` is pure except the explicitly named single-flight coordinator. The reducer owns UI phase, errors, successful-backup time, account scope and attempt ID. `SyncContext` owns effects, foreground triggers and pending counts. `syncAll` still owns replication order and RLS-backed I/O. Existing `syncing`, `lastErrors`, `lastSyncAt`, `pending` and methods remain available. Settings and journal no longer claim cloud backup before a successful sync; settings surface partial/error status before a zero pending count.

This does not cancel replication already running when an account changes, coordinate local wipe with writes, or partition the local database per account. These are separate, high-priority ownership transitions needing database/device integration tests; do not claim them solved by UI scope guards.

## Verification

From repository root: `node scripts/state-index.mjs --check`. In `apps/wayfare-mobile`: `npm run verify`. Existing CI also runs platform bundles and the SQL/RLS/HTTP suites. The new tests cover overlapping calls, account separation, stale results, retry after failure and truthful partial-backup timestamps. Before shipping, test foreground/manual overlap, offline retry, owner conflict, account switching, media failure, GPS mode switches and wipe during sync on isolated devices.

See [source-index.json](source-index.json) for file/line evidence and the companion Ariyoo inventory. Candidate scanning is deliberately broad and cannot prove that every possible runtime state machine has been found. Existing machine names and SQL enums are not blanket transition permissions.
